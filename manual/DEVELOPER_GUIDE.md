# HJ AI RAG 솔루션 서비스 개발자 매뉴얼

문서 버전: 1.1 · 기준일: 2026-09-12 · 대상: 솔루션을 도입해 서비스를 개발하는 외부 개발자

HJ AI RAG 솔루션은 등록된 지식 자료를 검색하고 그 근거를 바탕으로 답변을 제공하는 API 서비스입니다. 개발자는 이를 고객지원, 제품 안내, 업무 지식 검색 등에 연동할 수 있습니다. 이 문서는 도입 준비, 서비스 설계, 연동, 운영 검증을 설명합니다. 필드별 규격은 [외부 API 명세서](API_SPECIFICATION.md)를 참고하세요.

## 1. 제공 기능과 역할

| 기능 | API | 적용 예 |
|---|---|---|
| 지식 기반 답변 | POST `/knowledge/answers` | 제품 사용법, 업무 규정, 서비스 정책 안내 |
| 지식 검색 | POST `/knowledge/search` | 관련 자료 검색 화면, 근거 발췌 표시 |
| 저위험 일반 답변 | POST `/bedrock/general-answers` | 인사, 감사, 안정적인 기본 상식 안내 |

일반적인 질의응답 서비스는 지식 기반 답변 API 하나로 시작할 수 있습니다. 검색 API는 자체 검색 화면이 필요한 경우 사용합니다. 일반 답변 API는 제품·정책 질문에서 자료를 찾지 못했을 때 대신 답하게 하는 용도로 사용하지 않습니다.

| 담당 | 책임 |
|---|---|
| 솔루션 제공자 | 서비스 연결·인증키 제공, 지식 반영과 검색 준비, 허용 범위·운영 조건 관리 |
| 도입 서비스 개발자 | 사용자 인증, 조직별 요청 분리, API 호출, 화면·업무 흐름, 오류 처리 |
| 자료 담당자 | 원문의 정확성, 공개 가능 범위, 적용 기간, 변경·폐기 요청 |

지식 등록·갱신은 제공자와 합의한 자료 전달 절차로 진행합니다. 이 문서의 소비자 API는 검색과 답변 연동용입니다. 자료 관리 기능이 필요한 경우 도입 시 별도 제공 절차를 협의합니다.

## 2. 도입 준비

| 제공자에게 받을 정보 | 확인 내용 |
|---|---|
| API 기본 주소 | HTTPS 주소와 필요한 접두 경로 포함 여부 |
| 인증키 | 서비스별 appkey, 만료일, 교체 절차 |
| 데이터 범위 | 키로 접근할 수 있는 조직·제품·자료 |
| 검색 공개 범위 | 고객 공개 자료 또는 승인된 업무 자료 |
| 지식 준비 상태 | 자료 반영 완료 여부와 확인용 질문 |
| 운영 조건 | 사용 한도, 응답 대기 시간, 이용 조건, 지원 창구 |

예제 주소를 운영 주소로 사용하지 않습니다. 테스트와 운영의 키·자료를 구분합니다. 인증키는 서버의 비밀 설정에 보관하며 브라우저 코드, 모바일 앱 패키지, URL, 분석 도구, 오류 로그에 포함하지 않습니다. 키가 노출되었거나 만료가 임박하면 제공자에게 교체를 요청하고 서버 설정을 갱신합니다.

## 3. 지식 자료 준비

| 자료와 함께 전달할 정보 | 예 |
|---|---|
| 제목·버전 | 제품 설치 안내 v2 |
| 적용 대상 | 제품코드 PRODUCT_A, 지원 조직 |
| 적용 기간 | 시행일, 종료일 또는 종료일 없음 |
| 공개 범위 | 고객 공개 가능 또는 승인된 업무 사용자 전용 |
| 본문 | 조건, 절차, 예외 사항을 포함한 검토 완료 내용 |
| 확인 질문 | 답변되어야 하는 질문과 답변되면 안 되는 질문 |

모순되는 구버전·신버전이 함께 사용되지 않도록 적용일과 교체 대상을 전달합니다. 제품코드가 있는 개별 자료와 모든 제품에 적용되는 공통 자료를 구분하세요. 자료 반영 완료 후 확인용 질문으로 답변·출처를 검증하고 변경 때마다 재확인합니다. 지원 파일 형식·용량·반영 시간은 도입 시 합의한 조건을 따릅니다.

## 4. 서비스 연동 구조

```text
최종 사용자 → 도입 서비스 서버 → HJ AI RAG API
최종 사용자 ← 화면에 필요한 응답 ← 답변·판정·출처
```

도입 서비스 서버가 사용자를 인증하고 조직에 맞는 키와 검색 조건을 결정합니다. 사용자가 전송한 조직 식별값이나 검색 범위를 검증 없이 사용하지 않습니다. 서로 분리해야 하는 조직을 하나의 키로 연결하지 말고 제공자와 분리 구성을 협의하세요. 제품 필터는 접근 권한을 대신하지 않습니다.

API 요청은 서버에서 허용한 필드로 새로 구성합니다. 사용자 입력 객체 전체를 전달하지 않습니다. 응답도 답변, 판정, 허용한 출처 정보와 추적 ID만 선별해 고객 화면에 제공합니다.

### 첫 요청

1. API 기본 주소와 appkey를 서버에 설정합니다.
2. 질문의 공백을 정리하고 빈 질문은 전송하지 않습니다.
3. 사용자 권한으로 검증한 서비스 범위와 제품 조건을 결정합니다.
4. 답변 API를 호출합니다.
5. HTTP 성공 여부와 별도로 answerable·answerStatus를 확인합니다.
6. 답변과 실제 인용 출처를 표시합니다.

고객 공개 서비스의 권장 요청:

```json
{
  "query": "PRODUCT_A 설치 전에 확인할 사항을 알려주세요.",
  "strict": true,
  "includeSources": true,
  "includeSourceContent": false,
  "filters": {
    "accessLevels": ["PUBLIC"],
    "businessStatuses": ["PUBLISHED"],
    "productCodes": ["PRODUCT_A"],
    "activeAt": "2026-09-12T00:00:00.000Z"
  }
}
```

activeAt은 실제 조회 기준 시각으로 갱신합니다. 제품을 한정하지 않으면 productCodes를 생략할 수 있습니다. 고객 공개 서비스는 키의 허용 범위도 PUBLIC으로 설정되었는지 확인하세요. 필터 생략 시 공개·게시·현재 적용 자료로 자동 제한된다고 가정하면 안 됩니다.

## 5. 답변과 출처 처리

| 결과 | 서비스 동작 |
|---|---|
| answerable=true, answerStatus=answered | 답변과 인용 출처 표시 |
| answerable=false | 근거 부족 또는 답변 검증 실패에 대한 확인 필요 안내 |
| 알 수 없는 answerStatus | 확인 필요 상태로 처리 |
| HTTP 오류·연결 실패 | 이용 불가·재시도 안내와 추적 ID 제공 |

HTTP 200은 처리 성공이며 답변 가능을 뜻하지 않습니다. 답변 불가는 상품이나 정책이 존재하지 않는다는 뜻도 아닙니다. “등록된 자료에서 확인하지 못했습니다. 제품명이나 적용 조건을 추가하거나 담당자에게 문의해 주세요.”처럼 안내합니다.

sources는 실제 인용한 출처입니다. 검색 결과 수와 다를 수 있고 index가 연속적이지 않을 수 있으므로 인용 번호를 유지하세요. 출처명은 다운로드 링크가 아닙니다. 발췌문을 표시할 때는 최종 사용자의 원문 열람 권한을 확인합니다.

텍스트는 일반 텍스트 또는 안전하게 처리한 Markdown으로 표시하며 검증 없는 HTML로 삽입하지 않습니다. API 응답 전체를 고객에게 전달하지 않습니다.

대화 UI를 만들어도 API가 이전 대화를 자동으로 기억하지는 않습니다. 이력은 도입 서비스에서 관리하고 후속 질문에는 필요한 제품·조건을 포함해 독립적인 질문으로 전달합니다. 질문·답변 저장은 서비스의 보관 정책에 맞춰 범위와 기간을 정합니다.

## 6. 검색과 일반 답변 활용

검색 API는 관련 원문을 반환합니다. 점수는 유사도이며 정확도나 확률이 아닙니다. 결과가 없으면 빈 목록을 표시하고 질문을 구체화하도록 안내합니다. 원문 제공에는 사용자 권한을 적용합니다.

일반 답변은 등록 자료 기반 답변과 구분해 표시합니다. generalAnswerEligible=false 또는 reviewRecommended=true이면 담당자 확인 상태로 처리합니다. 제품·정책 질문이 자료에서 해결되지 않을 때 일반 답변을 자동 호출하지 않습니다.

## 7. 오류와 운영 처리

요청마다 UUID 형식의 x-correlation-id를 생성합니다. 응답 본문의 requestId 또는 x-correlation-id 응답 헤더를 문의·장애 추적에 사용합니다. 추적 ID는 인증키나 중복 방지 키가 아닙니다.

| 상황 | 처리 |
|---|---|
| 입력 오류 | 필드·타입 수정 |
| 인증 실패 | 키 만료·교체 상태 확인, 반복 자동 호출 중단 |
| 접근 거부 | 서비스 상태·허용 범위 확인 |
| 요청 제한 | 일시 부하·사용 한도 확인, 제한적 재시도 |
| 시간 초과·서버 오류 | 대기 종료, 제한적 재시도 또는 담당자 안내 |

대기 시간과 재시도 횟수를 정하고 재시도 간격을 늘리며 무작위 지연을 추가합니다. 응답을 받지 못해도 생성이 실행되었을 수 있어 중복 사용량이 발생할 수 있습니다. 같은 추적 ID를 보내도 중복 실행이 방지되지 않습니다.

로그는 호출 시각, 경로, HTTP 상태, 오류 code, 처리 시간, 추적 ID 중심으로 남깁니다. 인증 헤더와 전체 요청·응답을 무조건 저장하지 않습니다. 사용량 정보는 참고값이며 과금·한도 기준은 제공 계약을 따릅니다.

## 8. 출시 전 검증

| 항목 | 완료 기준 |
|---|---|
| 정상 질문 | 예상 자료에 근거한 답변·출처 표시 |
| 근거 없는 질문 | 확인 필요 상태, 일반 답변으로 자동 대체하지 않음 |
| 제품·기간 | 해당 제품·적용 기간의 자료 사용 |
| 조직·사용자 분리 | 다른 범위의 자료가 노출되지 않음 |
| 인증·입력 오류 | 명확한 안내, 무한 재시도 없음 |
| 통신 오류·지연 | 대기 종료·복구 동작 확인 |
| 필드 추가·생략 | 추가 속성 무시, 선택 속성 생략 처리 |
| 고객 응답 | 허용 필드만 반환, 인증키·부가 기술 정보 제외 |
| 지식 변경 | 대표 질문으로 최신 답변·출처 재검증 |

지원 요청에는 발생 시각·시간대, 대상 서비스, 호출 API, HTTP 상태, 오류 code, 추적 ID를 전달합니다. 인증키와 민감한 원문은 첨부하지 않습니다.
