### 지식 파일 방어선

핵심 구현은 [knowledge-file-security.ts](../src/knowledge/knowledge-file-security.ts)에 있습니다.

- 허용 확장자, MIME, 파일 내용 signature를 저장 전과 parser 전 두 번 검증
- PDF, XLS, DOCX, XLSX container marker 검증
- 빈 파일, 잘못된 UTF-8, 잘못된 JSON, 경로 포함 파일명 거절
- 기본 30MB, 허용 환경 범위 1~100MB
- Multer: 파일 1개, field 0개, `parts: 2`
- XLSX: formula/HTML/style/VBA 비활성화, 50 sheet·200,000 cell 상한

`parts: 1`은 정상 단일 파일 multipart를 `Too many parts`로 거절하는 것을 실제 HTTP에서 확인해 `parts: 2`로 조정했습니다. 이 값은 되돌리지 않습니다.

로컬 프로세스는 영속 서비스가 아닙니다. 다음 작업 시작 시 필요하면 직접 실행합니다.

```powershell
# 저장소 루트: AI Server
npm run build
npm run start:prod

# 별도 PowerShell, 저장소 루트에서: 검증 데모
Set-Location demo
node --env-file=../.env server.mjs
```

- AI Server: `http://127.0.0.1:11000/health/ready`
- 검증 데모: `http://127.0.0.1:11001`
- 데모 재기동 후에는 UI의 `검증 환경 구성`을 실행합니다. appkey와 demo profile은 데모 서버 메모리에만 유지됩니다.
- 로컬 `.env`는 Git 제외 대상입니다. secret을 출력·커밋하지 않습니다.
- CORS local allowlist는 11001, 11002를 모두 포함해야 합니다.

Compose에는 현재 AI Server만 실제 service로 정의되어 있습니다. 검증 데모와 서비스 데모의 운영 컨테이너·reverse proxy 반영은 아직 수행되지 않았습니다.

## 6. 알려진 위험·제약

`npm audit`에는 High 4건이 남아 있습니다.

- Prisma CLI 전이 경로: `prisma` → `@prisma/config` → `deepmerge-ts`
- `xlsx` 0.18.5의 prototype pollution/ReDoS 경고

`xlsx`는 파일 크기·signature·sheet/cell 상한으로 1차 격리됐지만 해결된 것이 아닙니다. `KNW-SRV-06`에서 parser 교체 또는 worker/process 격리를 수행해야 합니다. 강제 `npm audit fix --force`는 Prisma 메이저 역행을 유발하므로 사용하지 않습니다.

S3 업로드·다운로드는 아직 전체 buffer 방식입니다. `KNW-SRV-03` streaming 전환 전에는 단계 2의 대용량 memory exit gate를 만족했다고 판단하지 않습니다.

서비스 데모 브라우저에는 관리자·지식 운영자 credential을 전달하면 안 됩니다. 향후 서비스 데모는 BFF를 통해 공개 계약만 사용해야 합니다.

## 7. 다음 작업 권장 순서

### 1순위 — `KNW-DEM-04`

실제 `POST /admin/v1/knowledge/apps/:appId/files` multipart 계약을 검증 데모에 추가합니다.

| 사례 | 기대 결과 |
|---|---|
| 확장자/MIME 불일치 | HTTP 400 |
| PDF·DOCX·XLSX signature 손상 | HTTP 400 |
| 빈 파일·공백 파일 | HTTP 400 |
| `KNOWLEDGE_MAX_FILE_SIZE_MB` 초과 | HTTP 413 |

유의사항:

- 검증 데모 proxy의 body 한도는 40MB이므로 기본 30MB 경계 시험을 전달할 수 있습니다.
- 테스트에서 생성한 정상 파일은 `deleteObject=true`로 archive·S3 삭제까지 정리합니다.
- server 단위 회귀는 이미 있으므로, 이 작업은 browser/HTTP boundary와 구조화 오류 계약을 검증하는 데 초점을 둡니다.

### 2순위 — `KNW-SRV-03~06`

streaming, 업로드/DB 실패 보상, archive/S3 삭제 일관성, XLSX parser 교체·격리를 순서대로 진행합니다. 이 단계에서 각 실패 경로를 데모 scenario로 같이 추가합니다.

### 3순위 — 서비스 데모 `ENV-SVC-01~04`

`service-demo/`는 현재 포트 설정 파일만 있습니다. 독립 BFF 애플리케이션, persona fixture, correlation ID, loading/error 상태를 구축하되 11002를 사용하고 브라우저에 관리자 credential을 두지 않습니다.
