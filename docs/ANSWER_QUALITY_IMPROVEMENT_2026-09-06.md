# 서비스 데모 답변 품질 개선

## 개선 기준

단순히 답변률을 높이면 모르는 질문에도 답할 수 있다. 따라서 등록된 사실의 포함 여부, 출처, 올바른 거절, tenant 격리, 가격·재고의 최신성 한계, 읽기 쉬운 설명을 함께 평가한다. 모델은 Claude Sonnet 4.6 / Titan Text Embeddings V2를 유지한다.

## 이번 변경

| 문제 | 적용한 변경 |
|---|---|
| 목록·비교도 항상 1~3문장으로 제한 | 서버 소유 상담 지침과 detailed 답변 스타일. 간단한 질문은 짧게, 비교·목록은 항목별 설명 |
| 가격·재고를 실시간 사실처럼 오해할 수 있음 | 등록 자료 기준임을 명시하고 실시간 보장·없는 할인·상품 기능을 금지 |
| 교환 조건의 적용 설명이 부족할 수 있음 | 구매일·사용 여부와 기간·영수증·예외를 대조하고 고객이 말하지 않은 상황을 가정하지 않도록 지시 |
| 생성 한도 때문에 설명이 잘릴 수 있음 | 최대 생성 토큰 512 → 768. 실제 응답 길이는 질문에 맞추도록 지시 |
| 추천 질문과 화면 fixture가 운영 자료와 불일치 | 존재하지 않는 LED 스탠드 대신 실제 상품·가격 질문, 현재 매장 운영시간 질문 사용 |
| 검색 유사도 3%가 답변 신뢰도처럼 표시 | 고객 화면에서 퍼센트를 제거하고 실제 사용 문서를 표시. 검색 점수 자체는 API 데이터에 유지 |
| 줄바꿈이 화면에서 사라짐 | 답변의 줄바꿈을 보존하여 항목별 설명을 읽을 수 있도록 변경 |

직전 개선에서 제거한 임의 검색 하한은 계속 제거된 상태다. 검색은 최대 5개 후보, 해당 tenant의 게시 가능한 자료로 제한하고 strict 출처 판정을 유지한다. 상품명·가격을 답변 코드에 하드코딩하지 않았다. 화면의 데모 상품 소개만 운영 fixture와 맞췄다.

## 검증 방법과 한계

`scripts/evaluate-service-answer-quality.mjs`는 전용 서비스 데모의 STORE_A/B를 대상으로 목록, 예산, 비교, 재고, 교환 A/B, 운영시간, 없는 상품, 미정 입고일, 다른 매장 상품의 10개 질문을 기존/개선 설정으로 각각 호출한다. 평가 입력의 자격증명은 서버 내부에서만 사용한다. 결과에는 답변, 공개 문서명, 요청 ID, 지연과 판정만 남긴다.

이 검사는 실제 운영 AI 서버의 검색·생성 경로를 사용한다. 질문 확장과 서비스 UI를 포함한 완전한 BFF E2E 점수가 아니라 동일 질문에 대한 생성 정책 비교다. 정규식 기반 사실 포함/거절 검사는 표현에 민감하므로 실제 답변도 검토한다. 10문항·각 1회는 작은 회귀 표본이며 전체 정확도나 통계적 개선율로 일반화하지 않는다.

답변 설정의 회귀 테스트, 기존 인증·tenant·개인정보 경계 테스트와 전체 서비스 테스트를 함께 실행한다. 모델은 비결정적이므로 문장 자체를 정답 문자열로 고정하지 않는다.

실행 결과: 서비스 회귀 테스트 57건, TypeScript 검사, 빌드 통과. 실제 AI 비교 총 20회 모두 HTTP 200. 사실·출처·거절 기준은 기존 10/10, 개선안 10/10이다. 재고 답변에 자료 기준을 밝히는 항목을 추가한 품질 체크는 9/10 → 10/10이다. 이를 전체 정확도 10% 향상으로 해석하지 않는다.

실제 예: 기존은 “현재 재고는 42개이고 가격은 3,000원”이라고 했고, 개선안은 “등록 자료 기준으로 … 재고 42개 … 실시간 재고·가격과 다를 수 있습니다”라고 답했다. 목록·가격 비교는 줄바꿈한 항목으로 설명했다.

평균 지연은 기존 1,827.7ms, 개선안 4,552.5ms였다. 순차 실행한 각 10개 표본이고 후반 응답이 전반적으로 느려졌으므로 프롬프트 변경만의 인과 효과로 단정할 수 없다. 설명량과 시스템 입력 증가의 비용 가능성은 있다. 원본: `outputs/answer-quality/2026-09-06/comparison.jsonl`.

## 다음 개선 우선순위

1. 실제 질문을 개인정보 없이 분류하여 50~100문항의 평가셋을 확장한다. 상품 단문/오타, 조건 비교, 복합 질문, 근거 부족, tenant 경계를 각각 집계한다.
2. 검색 recall을 별도 평가한다. 상품코드·정확한 상품명은 키워드 검색, 의미 질문은 벡터 검색을 병합하고 문서별 후보 쏠림을 줄이는 방식을 비교한다. 한국어 임베딩 교체는 같은 평가셋에서 비용·지연·검색 recall을 측정한 뒤 결정한다.
3. 현재 상품·재고는 데모 문서다. 실제 상품 DB·재고 API를 연결하고 기준 시각을 표시해야 실시간 안내 품질을 높일 수 있다. 임의 상품 데이터를 늘리는 것은 하지 않는다.
4. 후속 질문의 문맥 처리와 모호한 질문의 되묻기를 별도 구현한다. 현재 대화는 화면에는 누적되지만 각 서버 질문은 독립 요청이다. 이전 대화를 사실 근거로 취급하지 않는 설계와 tenant 전환 초기화 검증이 필요하다.
5. 부분 답변과 근거 부족 사유를 API 계약으로 분리한다. 현재 서버는 근거 부족 시 공통 거절 문구를 반환하므로 서비스 프롬프트만으로 모든 질문에 상세한 부족 사유를 전달할 수 없다.
6. 상담원 피드백·영구 검토함과 연결해 실패 질문 → 자료 보완 → 회귀 검증 흐름을 만든다. 현재 영구 검토함은 미구현이다.

운영 영향을 제한하기 위해 이번에는 서버 API 계약·데이터·모델을 변경하지 않고 서비스 BFF의 상담 지침과 표시를 개선했다. 상세 답변은 지연·토큰 사용을 늘릴 수 있다. 높은 답변률보다 근거 정확성과 올바른 거절을 우선한다.
