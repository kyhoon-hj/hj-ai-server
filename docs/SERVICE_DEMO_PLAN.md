# 서비스 데모 개발 계획

작성일: 2026-08-18
상태: 구현 착수 기준
상위 계획: [AI Server·검증 데모·서비스 데모 통합 로드맵](DEMO_AI_SERVER_INTEGRATED_ROADMAP.md)

## 1. 목적

`service-demo/`는 AI Server의 내부 검증 화면이 아니라 실제 서비스를 가정한 소비자 애플리케이션입니다. 첫 번째 제품 시나리오는 마트 고객응대이며, 해당 계약과 운영 기준이 안정된 뒤 매출 자료 분석으로 확장합니다.

검증 데모 `demo/`가 PASS/FAIL과 기술 증거를 제공한다면, 서비스 데모는 고객·상담원·매장 관리자가 업무를 끝까지 수행할 수 있는지 확인합니다. 서비스 데모의 화면 동작만으로 서버 기능 완료를 판정하지 않습니다.

## 2. 범위와 비범위

### 첫 번째 범위 — 마트 고객응대 MVP

- 고객의 상품·운영시간·교환·환불 질문
- 근거 문서를 포함한 답변
- 답변 불가와 상담원 검토 요청
- 상담원의 답변·source 확인과 피드백
- 매장 관리자의 지식 문서 등록과 처리 상태 확인
- STORE_A/STORE_B tenant 격리 시연

### 두 번째 범위 — 매출 자료 분석

- CSV/XLSX 매출 자료 업로드와 schema 검증
- 기간·매장·상품별 결정론적 집계
- KPI와 비교 차트
- 집계 결과를 근거로 한 AI 설명
- 분석 이력과 리포트

### 초기 비범위

- 실제 결제·주문·환불 처리
- 실제 고객 개인정보 사용
- LLM을 이용한 원본 매출 직접 합산
- 검증되지 않은 AI Server 내부 endpoint 직접 호출
- production 관리자 credential의 브라우저 전달

## 3. 사용자와 대표 여정

| 사용자      | 대표 목표                           | 핵심 여정                                     |
| ----------- | ----------------------------------- | --------------------------------------------- |
| 고객        | 빠르고 근거 있는 안내 받기          | 질문 → 답변/source 확인 → 해결 또는 상담 요청 |
| 상담원      | AI 답변을 검토하고 미해결 문의 처리 | 대기 문의 → 답변/source 검토 → 피드백·응답    |
| 매장 관리자 | 지식과 분석 자료를 안전하게 관리    | 파일 등록 → 처리 상태 → 게시·검색 확인        |
| 영업 관리자 | 정확한 매출 변화와 원인 후보 확인   | 자료 등록 → 필터·집계 → AI 설명·근거 확인     |

## 4. 애플리케이션 경계

```text
브라우저
  → service-demo BFF
    → AI Server 공개 /v1 API
      → PostgreSQL / S3 / Bedrock

검증 데모
  → 동일 AI Server 계약을 독립적으로 검증
```

- 브라우저는 관리자·지식 운영자 credential을 보관하거나 직접 전송하지 않습니다.
- BFF는 서비스 세션을 AI Server app/role context로 변환합니다.
- AI Server의 OpenAPI와 generated client를 서비스 데모의 계약 기준으로 사용합니다.
- 서비스 데모 전용 mock은 UI 개발에만 사용할 수 있으며 완료 증거에는 포함하지 않습니다.

## 5. 개발 단계

### S0 — 골격과 공통 UX

- 프로젝트 실행·build·test 구조
- 환경별 AI Server URL
- API client와 correlation ID
- loading, empty, error, permission denied 공통 상태
- persona와 개인정보 없는 fixture

완료 조건: 로컬에서 서비스 데모가 실행되고 AI Server health 상태를 올바르게 표시합니다.

### S1 — 고객응대 MVP

- 고객 채팅과 추천 질문
- 답변 본문과 source 카드
- strict no-answer와 상담원 연결
- 매장 관리자 지식 업로드와 상태 확인
- tenant별 테마와 데이터 분리

완료 조건: 환불·교환·운영시간·상품 문의 대표 여정이 실제 `/v1` API로 동작하고 대응하는 검증 데모 시나리오가 PASS합니다.

### S2 — 장애와 운영 UX

- 인덱싱 job 진행·실패·재시도
- 429·timeout·quota 초과 안내
- 중복 제출 방지
- correlation ID 기반 문의 지원
- 상담원 검토함과 피드백

완료 조건: 일시 장애와 영구 실패를 구분하며, 사용자가 안전하게 재시도할 수 있습니다.

### S3 — 품질·성능·배포

- golden question 시연 모드
- source 적중과 no-answer UX 확인
- 응답 체감 시간과 성공률 측정
- 접근성·반응형·브라우저 기본 검증
- staging smoke와 fixture reset

완료 조건: 통합 로드맵 단계 6의 최종 Exit Gate를 통과합니다.

### S4 — 매출 자료 분석

- 매출 schema 오류 안내
- KPI·기간 비교·상품/매장 필터
- 결정론적 집계와 근거 표시
- 자연어 분석 질문과 AI 설명
- 분석 이력·리포트 저장

완료 조건: 모든 표시 수치가 서버 집계 결과와 일치하고 AI 설명의 임의 수치가 0건입니다.

## 6. 화면 구성 초안

| 영역        | 화면                                                |
| ----------- | --------------------------------------------------- |
| 고객        | 홈, 고객 채팅, source 상세, 상담 요청               |
| 상담원      | 검토 대기함, 문의 상세, AI 답변·source 검토, 피드백 |
| 매장 관리자 | 지식 목록, 업로드, 처리 상태, 정책·게시 상태        |
| 영업 관리자 | 매출 업로드, KPI 대시보드, 비교 분석, 리포트        |

고객응대 MVP에서는 고객 채팅과 최소 관리자 업로드 화면만 구현합니다. 상담원 고도화와 매출 화면은 앞 단계 Exit Gate 이후 확장합니다.

## 7. 완료 정의

서비스 데모 작업은 다음 조건을 모두 만족해야 완료입니다.

- 대표 사용자 여정과 기대 상태가 문서화됨
- 실제 AI Server 공개 계약을 사용함
- 대응하는 검증 데모 시나리오 PASS
- loading, empty, error, retry 상태 처리
- tenant·role·credential 회귀 없음
- correlation ID와 진단 가능한 오류 표시
- 접근성 기본 점검과 자동 smoke PASS
- 환경변수·배포·fixture reset 절차 문서화

## 8. 착수 백로그

1. `service-demo/` 기술 골격과 실행 명령
2. 마트 persona와 환불·교환·운영시간·상품 문의 사용자 여정
3. 공개 `/v1/answers` 응답과 source UI 계약
4. 공통 API client와 오류·correlation ID 처리
5. 고객 채팅·source·no-answer 화면
6. 관리자 지식 업로드·인덱싱 상태 화면
7. 대표 여정 smoke test
