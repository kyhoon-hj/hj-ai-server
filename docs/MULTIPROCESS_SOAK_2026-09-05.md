# 별도 워커 프로세스와 운영 lease의 지속 처리 시험

2026-09-05. `npm run test:multiprocess-soak`로 실행한다. 테스트 전용 child 프로세스 3개가 실제 PostgreSQL 대기열을 처리한다. 운영 워커 코드는 변경하지 않았다.

## 조건과 판정 기준

- 작업 공급 시간 390초(6분 30초), 공급 종료 후 최대 30초 안에 잔여 작업 완료. 워커 시작 시간은 별도이며 DB 초기화와 최종 종료도 공급 시간에서 제외한다.
- 동일 파일 6개를 반복 재인덱싱한다. 파일당 42,769바이트, 16청크로 전체 최신 인덱스는 96청크다. 완료된 파일은 검사 후 새 작업을 공급하므로 파일별 활성 작업은 최대 1개다.
- 다운로드와 embedding은 서비스 경계의 합성 adapter다. embedding은 청크당 50ms 지연과 1024차원 고정 벡터를 반환한다. AWS SDK·네트워크 응답 부하는 이번 프로세스 시험에서 제외한다.
- KnowledgeService의 실제 파싱·청킹·인덱스 트랜잭션과 KnowledgeIndexJobService의 자동 polling·heartbeat·기본 lease 300,000ms를 사용한다. 테스트에서 lease 값을 줄이거나 DB 시각을 변경하지 않는다.
- 처리 시작 15초 이후 첫 워커가 processing 상태일 때 강제 종료하고 새 프로세스를 시작한다. 종료 직전 lease 잔여 시간이 290초를 넘는지 검사한다.
- 종료된 작업은 lease 만료 이전에 완료되지 않아야 하며, 만료 후 10초 안에 attempt 2로 완료되어야 한다. 그 사이 다른 워커가 100개 넘는 작업을 완료해야 한다.
- 매 완료 시 16개 청크의 번호·내용·벡터 차원과 첫 성분을 검사한다. 정상 작업은 attempt 1, 종료된 작업만 attempt 2여야 한다. 마지막에는 queued/processing/failed 작업이 없고 최신 청크가 96개인지 확인한다.
- 새 워커 3개를 정상 종료하고 exit code 0을 확인한다. 종료된 테스트 프로세스와 파일·작업·임시 DB는 정리한다.

## 자원 기록

워커가 IPC로 1초 간격의 PID·RSS·heapUsed·CPU user/system 시간 차이를 전달한다. 최초 종료된 PID와 재시작된 PID를 구분해 JSON에 저장한다. 같은 격리 DB의 `application_name=soak-worker` 연결 수는 관측용 연결에서 1초 간격으로 집계한다. 워커 pool은 각각 최대 2개다.

CPU·메모리는 실제 워커 프로세스 지표이며 ts-node 런타임과 합성 adapter를 포함한다. DB 서버 CPU·메모리 및 전체 호스트 지표는 아니다. JSON의 CPU 값은 각 PID에서 수집한 누적 CPU 시간이고, 최대 RSS는 표본 최댓값이다. 프로세스별 RSS를 서로 다른 시점의 최댓값끼리 합쳐 동시 총 사용량으로 해석하지 않는다.
