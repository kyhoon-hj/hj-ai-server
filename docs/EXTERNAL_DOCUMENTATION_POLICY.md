# 외부 개발자 문서 배포 기준 — 내부 관리용

기준일: 2026-09-12 · 구현 대조 기준: 73f0cbd

## 대상과 배포 단위

외부 문서의 독자는 AI RAG 솔루션으로 자체 서비스를 만드는 도입사 개발자다. 데모 화면 사용자 매뉴얼이나 플랫폼 운영자 설명서를 섞지 않는다.

외부 배포는 프로젝트 루트 `manual/`의 DEVELOPER_GUIDE.md, API_SPECIFICATION.md만 대상으로 한다. 저장소 루트 README, docs 전체, 과거 API 초안, 배포 기록, 전체 Swagger를 함께 배포하지 않는다. 외부 문서에서 내부 문서·소스 파일로 링크하지 않는다.

## 선정한 소비자 계약

| 경로 | 선정 이유 |
|---|---|
| POST /knowledge/answers | 근거 기반 답변 |
| POST /knowledge/search | 관련 지식 검색 |
| POST /bedrock/general-answers | 별도 용도의 저위험 일반 답변 |

호환 답변 별칭, 파일 목록·상세, 저장소, 범용 모델 직접 호출, 앱 발급·회전·감사, 지식 운영, 상태 진단, 특정 서비스 전용 대화·가족 지식 계약은 외부 공통 명세에서 제외한다. 제외 API의 경로나 관리자 인증 헤더도 외부 문서에 열거하지 않는다.

모델·프롬프트 재정의, 생성 엔진 설정, 특정 소비자 전용 보조 근거 입력은 외부 공통 요청 명세에서 제외한다. 응답은 고객 개발에 필요한 필드만 기술하고 저장소 위치, 모델 식별값, SDK·인프라 측정값, 내부 메타데이터 구조는 제외한다. 발췌 응답을 전체 응답으로 오해하지 않도록 실제 응답에는 추가 필드가 포함될 수 있음을 명시한다.

## 문서 공개와 런타임 차단의 구분

이번 수정은 외부 배포 문서의 선별이다. 서버 컨트롤러, 가드, 응답 직렬화, 프록시와 Swagger 생성 코드는 변경하지 않았다. 문서에서 제외한 경로·필드가 서버에서도 제거되거나 차단되었다고 보고하지 않는다.

현재 전체 Swagger는 여러 역할의 경로를 포함할 수 있고 소비자 응답에도 내부 부가 필드가 포함된다. RAG 요청은 현재 modelId/system 등의 필드를 허용한다. 문서 생략만으로 서버에서 차단된 것으로 간주하면 안 된다.

실제 제품 공개 경계의 강제가 필요하면 별도 서버 변경으로 소비자 경로 allowlist, 공개 요청·응답 DTO, 역할별 문서 생성, 프록시 노출 범위를 검토·검증해야 한다. 문서 검사는 런타임 검증을 대체하지 않는다.

## 개정 시 검증

1. 외부 문서의 경로가 선정한 세 POST API 범위에 머무는지 확인한다.
2. 내부 경로·인증정보·배포 주소·소스 링크·데모 화면 안내가 포함되지 않았는지 검사한다.
3. 요청 필드·기본값·응답 상태를 실제 DTO·서비스와 관련 계약 테스트에 대조한다.
4. 상대 링크가 외부 문서 디렉터리를 벗어나지 않는지 검사한다.
5. JSON 예제와 서버 호출 예제의 문법, 정상·답변 불가·오류 분기를 검증한다.
