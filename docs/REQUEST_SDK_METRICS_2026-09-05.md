# 요청 단위 AWS 측정

전역 Nest interceptor가 HTTP 요청마다 AsyncLocalStorage 수집기를 만들고 공통 runAwsRequest 경로의 성공·실패 메타데이터를 모은다. 성공한 일반 JSON 객체 응답과 오류 필터 응답에 awsRequest를 추가한다. 배열·스트림 응답은 원래 형태를 유지하며 이 응답에는 집계를 추가하지 않는다.

- scope: request-wrapped-aws-operations
- operations / completedOperations / measuredOperations: 시작된 래퍼 작업, 완료된 작업, attempts가 측정된 작업 수
- complete: 모든 시작 작업이 완료되고 attempts가 측정되었는지 여부
- attempts / retryCount: complete일 때만 합계. 호출이 없으면 명시적인 0
- totalRetryDelayMs: 모든 작업의 지연 메타데이터가 있을 때만 합계

검색 임베딩과 생성은 각각 공통 호출 경로를 사용하므로 함께 집계된다. 실패 응답에는 그전에 성공했던 호출도 포함한다. 응답 완료 시 수집기를 닫아 이후 작업이 이미 반환된 집계를 변경하지 못하게 한다. 컨트롤러 이전 가드에서 거절된 요청에는 수집기가 없을 수 있다.

이 수치는 공통 래퍼가 관측한 작업 범위다. 복합 다운로드는 중첩 래퍼가 있고 멀티파트 업로드는 개별 SDK 메타데이터를 반환하지 않으므로 operations를 항상 SDK 명령 수로 해석하면 안 된다. 이러한 경로는 불완전 측정으로 남겨 총횟수를 확정하지 않는다. 배경 작업·직접 SDK 호출·응답 뒤 작업까지 포괄하는 프로세스 전체 통계가 아니다.

데모는 요청 총 시도·재시도·지연의 평균 및 p50/p95와 측정 응답 수를 집계한다. 화면과 비교 표에 총 시도 및 재시도 지연 p95를 추가했다. 기존 생성/실패 호출 지표와 호환한다. 이전 retries.serverSdkAttempts는 기존 null을 유지하며 새 요청 합계는 summary.awsRequest를 사용한다.

## 검증

서버 210개, 데모 51개 테스트 통과. 동시 요청 격리, 검색·생성에 해당하는 연속 호출 합계, 실패 전 성공 호출 보존, 일부 누락 및 호출 없음, 데모 측정 분모를 검증했다. 빌드·타입 검사·린트 통과. 실제 AWS 호출 및 브라우저 재검증은 실행하지 않았다.
