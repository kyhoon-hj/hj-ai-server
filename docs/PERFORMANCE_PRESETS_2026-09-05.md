# 성능 프리셋과 실행 비교

2026-09-05. 검증 데모의 성능 탭에 부하 프리셋과 실행 JSON 비교 기능을 추가했다. AI Server 생산 코드·운영 설정은 변경하지 않았다.

## 프리셋과 실행

| 프리셋 | 전체 요청 | 동시 요청 |
| --- | ---: | ---: |
| Smoke(화면 기본) | 5 | 1 |
| Baseline | 20 | 2 |
| Burst | 50 | 5 |
| 직접 설정 | 1~200 | 1~20, 전체 요청 이하 |

브라우저와 서버가 같은 프리셋 정의를 사용한다. 프리셋 선택 중 수량은 읽기 전용이며 서버도 프리셋 수치를 적용하므로 별도 total/concurrency 값으로 우회하지 않는다. 직접 설정은 정수만 허용한다. 잘못된 프리셋·NaN/소수·범위 초과는 호출 전에 400으로 반환한다. preset을 생략한 기존 API 요청은 직접 설정으로 처리한다.

선택만으로 시험이 실행되지는 않는다. 실행 중 버튼을 비활성화해 같은 화면의 중복 제출을 막는다. 이 제한은 여러 클라이언트의 동시 실행을 합산하는 전역 rate limit이 아니다.

실행 리포트 configuration에 preset을 저장하고 시작 시각을 실제 요청 시작 전에 기록한다. finishedAt도 추가했다. 서버의 기존 JSON 저장을 유지하며 화면에서도 현재 실행 JSON을 다운로드할 수 있다.

## 비교와 보존

현재 결과를 기준으로 지정한 뒤 다음 실행을 비교하거나, 이전에 저장한 성능 실행 JSON(최대 5MB)을 기준으로 불러온다. 기준은 현재 브라우저 메모리에 보관하며 페이지를 새로 열면 다시 지정해야 한다. 가져온 JSON은 서버로 전송하지 않는다.

비교 표는 성공률·처리량·전체/검색/생성 p95·평균 토큰·측정 응답 수의 기준/현재/차이/변화율을 표시한다. 차이는 현재−기준이며 성공률의 절대 차이는 퍼센트포인트다. 기준값 0의 변화율은 계산 불가, 누락된 측정은 미측정으로 표시한다. 조건 객체의 키 순서가 다른 것만으로 차이를 만들지 않는다.

API·서버 URL·기록된 버전·본문/query·요청 수·동시성·서버 maxTokens가 다르면 조건 차이를 알린다. 비교 JSON은 조건의 기준/현재 값과 계산 결과를 함께 내보낸다. 기록된 조건이 같아도 실제 서버 버전·데이터·반복 변동의 동일성을 보장하지 않으며 자동 성능 합격 판정을 하지 않는다.

업로드 JSON은 type·operation·configuration·주요 summary를 확인한 뒤 사용한다. 표시할 문자열은 DOM textContent로 처리한다. 비교 JSON은 실행 JSON과 형식이 달라 기준 실행으로 다시 가져올 수 없다.

## 검증

- 데모 테스트 47개 PASS. 새 6개 테스트는 프리셋 우선 적용, 사용자 입력 경계, 차이/변화율, 0·누락, 조건 비교, 잘못된 JSON 형식을 검사한다.
- 실제 demo/server.mjs를 별도 로컬 합성 HTTP 서버에 연결해 health operation의 Smoke 5회·Baseline 20회·Burst 50회 호출 및 성공률 100%를 확인했다. 잘못된 프리셋·소수 요청 수·동시성 초과는 400, 추가 upstream 호출 0회였다.
- 서버 실행 리포트는 `demo/reports/performance-2026-09-05T04-39-31-636Z.json`, `performance-2026-09-05T04-39-31-655Z.json`, `performance-2026-09-05T04-39-31-681Z.json`에 저장됐다.
- Playwright: Smoke 기본값, Burst 전환(50/5), 기준 지정 후 차이 표시, 실행/비교 JSON 다운로드, 실행 JSON 재가져오기 확인. 화면은 합성 리포트이며 AWS 지연 측정이 아니다. 표본 이미지 `output/playwright/performance-comparison.png`.
- JavaScript 구문 검사 및 diff whitespace 검사 PASS. 시험용 데모·합성 서버·브라우저 종료 완료.
